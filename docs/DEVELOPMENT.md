# Development and CI Guide

This guide is for contributors and maintainers. The project currently has a Flutter/Dart app foundation and does not yet have persistent imports or broad Facebook export support.

## Local development

Install Flutter stable (Flutter 3.38.4 or newer and Dart 3.13 or newer are required by `pubspec.yaml` and `pubspec.lock`), then run:

```sh
flutter create --platforms=windows --project-name personal_data_agent .
flutter pub get
dart format .
flutter analyze
flutter test
```

The platform runner files and `pubspec.lock` are generated by Flutter tooling and should be reviewed and committed when preparing a reproducible release. Do not add real personal exports, databases, credentials, or API keys to source control or CI artifacts. Tests should use synthetic or properly de-identified fixtures.

## GitHub Actions: Windows CI and build

Workflow: [`.github/workflows/windows-build.yml`](../.github/workflows/windows-build.yml)

The workflow runs on source/configuration changes in pushes and pull requests, and can also be started manually from the Actions tab. It provisions a Windows runner, generates the Windows runner project, installs dependencies, runs `flutter analyze` and `flutter test`, builds a Release version, then uploads the runnable folder as `personal-data-agent-windows-x64` for seven days.

To retrieve a successful build:

1. Open the repository's **Actions** tab.
2. Select **Flutter CI and Windows build** and open a successful run.
3. Download the `personal-data-agent-windows-x64` artifact.
4. Extract the ZIP and run `personal_data_agent.exe` from the extracted Release folder.

Keep all accompanying DLL files and the `data` folder next to the executable. This is a portable build folder, not an installer.

If the Actions tab is missing or the workflow does not start, check **Repository Settings → Actions → General → Actions permissions**. An organization or enterprise policy can override repository-level settings. The workflow definition itself belongs in `.github/workflows/`, not in repository Settings.

## GitHub Codespaces

The [`.devcontainer/`](../.devcontainer/) configuration installs a pinned Flutter stable SDK and Linux desktop build prerequisites. Create a Codespace from **Code → Codespaces**, wait for the container setup to finish, then run:

```sh
flutter analyze
flutter test
```

Codespaces runs Linux and is useful for editing, analysis, and tests; it does not produce a Windows executable. The Windows Actions runner handles that build.

## Usage and billing

Repository workflow permissions are configured in **Repository Settings → Actions → General**. Usage limits and spending controls are account-level (or organization-level) settings under **Settings → Billing and licensing**. Limits depend on the account that owns the repository and its plan. The repository is private, and GitHub-hosted Windows runner minutes are metered at a higher rate than Linux minutes. The current workflow narrows runs to relevant project changes and retains the build artifact for seven days.

Check the owner's Actions and Codespaces usage and budgets before increasing frequency, artifact retention, or machine size. Stopped Codespaces can continue to use storage while they exist; delete unused environments when finished. No paid usage, spending limit, or self-hosted runner is enabled by this guide.

## Current product scope

The app currently inspects ZIP archives locally and offers an in-memory preview for a limited Facebook messages JSON shape. It does not yet persist imported data or provide full search, analytics, or broad export-format coverage. Confirm the exact format against a permitted, de-identified sample before extending the parser.
