# مواصفات واجهة Tmewai

## 1. الهدف

واجهة Desktop هادئة ومفهومة للأرشيفات الشخصية. الأولوية لشرح ما نقرأه وما لا نقرأه، وللتنقل إلى المصدر، لا لإبهار المستخدم بإجابات غير قابلة للتحقق.

## 2. المبادئ البصرية والتفاعلية

- RTL افتراضيًا للعربية، مع بقاء الاقتباسات/المعرّفات/الروابط قابلة للقراءة LTR.
- دعم الإنجليزية في V1، وتبديل لغة ظاهر في الإعدادات.
- تخطيط Desktop: Sidebar بعرض تقريبي 220–250px، Topbar، ومحتوى مركزي بعرض قراءة 760–1100px.
- ألوان محايدة عالية التباين، لون accent واحد، semantic success/warning/error.
- الرسوم دائمًا لها جدول/وصف بديل؛ لا تعتمد على اللون وحده.
- keyboard focus واضح، tab order منطقي، وأهداف تفاعل لا تقل تقريبًا عن 40px.
- حالات loading/empty/error مخصصة، مع عدم التظاهر بنسبة تقدم غير حقيقية.
- عيّنات المحتوى قصيرة، ولا ينسخها التطبيق تلقائيًا إلى clipboard.

## 3. الهيكل الرئيسي

### Sidebar

1. نظرة عامة
2. بحث
3. الخط الزمني
4. المحادثات
5. العلاقات
6. تقرير الأنماط
7. إعدادات/خصوصية

- زر “تغيير مساحة العمل” إذا أضيف تعدد الملفات الشخصية لاحقًا.
- مؤشر بسيط لحالة الفهرس (جاهز/يحتاج تحديث).
- عنصر الصفحة الحالية واضح بصريًا وغير معتمد على اللون فقط.

### شريط علوي

- عنوان الشاشة ومسارها.
- البحث العام يظهر بعد توافر فهرس.
- اختيار مساحة البيانات/المنصة لاحقًا.
- مؤشر “محلي” يشرح بوضوح إن كان هناك أي اتصال خارجي.

## 4. الشاشات بالتفصيل

### 4.1 الترحيب

**العنوان:** افهم أرشيفك، مع بقاء بياناتك على جهازك.

- جملة توضح أن النسخة الأولى تقرأ فقط صيغ التصدير المدعومة.
- CTA: «اختر ملف تصدير» و«افتح مجلدًا».
- رابط «كيف نحمي الخصوصية؟».
- لا بطاقة تسويق توحي بدعم كل المنصات أو التحليل النفسي الدقيق.

### 4.2 استيراد وفحص

- Drop zone، وزر اختيار ملف/مجلد؛ لا يُجبر المستخدم على رفع الملف إلى الإنترنت.
- شريط يبيّن اسم الأرشيف، الحجم، ونوع الاختيار.
- بعد الفحص: بطاقات «قابل للقراءة»، «غير مدعوم»، «يحتاج انتباهًا».
- بيان الفئات التي وُجدت داخل الأرشيف لا يعني اكتمال سجل الحساب.
- زر متابعة يتطلب فهم سياسة التخزين المحلية والموافقة على إنشاء مساحة.
- حدود الحجم تظهر قبل المعالجة مع طريقة آمنة لاختيار مجلد مُصدّر أصغر إذا كان مناسبًا.

### 4.3 التقدم والنتيجة

مراحل: فحص الأرشيف ← تحديد الملفات ← قراءة البيانات المدعومة ← بناء الفهرس ← إنهاء.

- يعرض تقدمًا حقيقيًا بعدد ملفات/سجلات عند إمكان ذلك، دون تقدير زائف بالدقيقة.
- زر إلغاء دائم الظهور.
- بعد النجاح: ملخص أعداد، عدد الملفات التي لم تُقرأ، روابط لتقرير التفاصيل.
- عند الفشل: رمز تشخيص آمن ومعرّف داخلي؛ لا نعرض dump حساسًا.
- الإلغاء والفشل يوضحان ما إذا كانت مساحة العمل بقيت سليمة.

### 4.4 النظرة العامة

- نطاق التاريخ المتاح كما استُخرج، ونسبة/حدود المصدر لا ادعاء التغطية.
- مؤشرات: عدد السجلات المدعومة، أشهر النشاط، توزيع الحدث.
- قسم «ملاحظات عن البيانات» يذكر الفئات غير المتوفرة.
- قائمة أحدث أحداث مع رابط للمصدر.
- رسوم تعرض جدولًا بديلاً وتفسير الحساب.

### 4.5 البحث المتقدم

المرشحات:

- كل الكلمات/العبارة الدقيقة.
- بداية ونهاية التاريخ.
- نوع الحدث، المصدر/المنصة، الشخص، المحادثة.
- تضمين/استبعاد أنواع محددة إن كان تنفيذها آمنًا ومفهومًا.
- الترتيب: الأحدث أو الأكثر صلة.

كل نتيجة: نوع الحدث، التاريخ ودقته، مقتطف محدود، المشاركون كما وردوا، المصدر، زر «عرض الحدث». المرشحات النشطة تظهر كشرائح قابلة للإزالة. يجب ألا تؤدي علامات FTS أو الاقتباسات الخاطئة إلى crash أو SQL injection.

### 4.6 المحادثة

- تسلسل الرسائل مع اسم المشارك كما ورد في المصدر.
- تنبيه عند وجود رسائل/توقيتات ناقصة.
- مرشح زمني، بحث داخل المحادثة، الانتقال لرسالة حولها سياق.
- لا نعيد كتابة أو تصحيح محتوى المصدر بصمت.

### 4.7 الخط الزمني

- محاور حسب اليوم/الشهر مع تجميع كثافات النشاط.
- اختيار المقياس (رسائل/أحداث مدعومة) وتعريفه.
- لا تخلط تواريخ جهاز المستخدم مع UTC دون تحويل معلن.
- عند نقص التاريخ، قسم منفصل «تاريخ غير معروف».

### 4.8 شبكة العلاقات

- العقدة تمثل شخصًا أو محادثة حسب مصدر واضح.
- حجم/وزن الحافة يشرح (عدد الأحداث) وليس «قرب العلاقة».
- قائمة بديلة للرسوم وتصفية زمنية/نوعية.
- منع استنتاجات نفسية/مشاعر الطرف الآخر.

### 4.9 Agent Chat

1. اختيار مجموعة البيانات والفترة والفئات المسموح بها.
2. إدخال السؤال مع تذكير أن البيانات المستوردة قد تكون ناقصة.
3. تجهيز retrieval محلي؛ لا اتصال في هذه المرحلة.
4. معاينة الأدلة المقترحة واسم المزود والنموذج وسياسة الاحتفاظ/التكلفة.
5. إرسال بعد موافقة واضحة لهذا الطلب، مع إمكانية إزالة مقتطفات.
6. رد بأقسام: إجابة متحفظة، أدلة وروابط، حدود البيانات، درجة ثقة وصفية.
7. أزرار نسخ/تقييم/حذف، مع عدم تخزين الطلب خارجيًا دون علم.

حالات UI: لا API key، مفتاح غير صالح، لا اتصال، تجاوز ميزانية، لا أدلة كافية، provider refusal، إلغاء.

### 4.10 تقرير «من أنا؟»

- لا يُعرض إلا إذا فُعّل صراحة وبعد شرح أنه تحليل انعكاسي غير سريري.
- لكل ملاحظة: أدلة المصدر، الفترة، عدد الأمثلة، تفسير بديل، حدود الاستنتاج.
- أدوات تصحيح/إخفاء/حذف الملاحظة.
- لا صفات مرضية أو تقييمات قطعية.

### 4.11 الخصوصية والإعدادات

- حالة التخزين ومكان DB وعدد الملفات/الحجم التقريبي.
- إعداد المزود ومفتاح مخفي مع زر «حذف المفتاح» واختبار لا يرسل بيانات الأرشيف.
- إعداد الموافقة الدائمة إن وجدت، الافتراضي مغلق.
- زر حذف workspace مع تعداد ما سيحذف وما لا يمكن ضمان محوه ماديًا.
- روابط سياسة الخصوصية والتراخيص والإصدارات.

## 5. حالات عامة مطلوبة

- تحميل أولي، أول استخدام، لا بيانات، نتائج فارغة.
- صلاحية ملف غير موجودة، أرشيف مشوه، حجم زائد، محتوى غير مدعوم.
- استيراد جزئي مع تحذيرات صريحة.
- مساحة تالفة ومساعدة الاستعادة/التصدير.
- فشل قاعدة البيانات دون إفشاء query أو محتوى.
- تكبير نافذة/تصغيرها ودقة شاشة أقل.
- RTL للنصوص والرموز والأسهم والرسوم.

## 6. قواعد النص والمصطلحات

- “وجدنا في الأرشيف” وليس “كل نشاطك”.
- “البيانات المتاحة” وليس “حقيقة شخصيتك”.
- “تاريخ المصدر” مع توضيح المنطقة الزمنية.
- تجنب “آمن 100%”، “مشفر” أو “محلي بالكامل” إلا إذا كانت صحيحة ومختبرة لكل مسار.
- لا نعرض نصًا خامًا طويلًا من ملف في error snackbar/log.
