# خطة تنفيذ Tmewai

> **حالة الوثيقة:** مخطط تنفيذي تأسيسي، 23 تشرين الأول 2026. هذه الوثيقة تصف هدف المنتج؛ لا تعني أن جميع الوظائف المذكورة منفذة. يجب التحقق من إصدارات SDK والسياسات والمنصات وقت كل إصدار.

## 1. الرؤية وحدود المنتج

تطبيق Desktop محليّ أولًا يساعد المستخدم على استيراد نسخة بيانات حصل عليها بنفسه عبر أدوات التصدير الرسمية للمنصة، وفهرستها والبحث فيها وتحليلها، ثم طرح أسئلة اختيارية على AI اعتمادًا على أدلة من بياناته.

### مبادئ غير قابلة للتفاوض

1. التحليل المحلي الأساسي يعمل من دون حساب، شبكة، أو مفتاح API.
2. لا نرفع الأرشيف إلى خوادمنا في النسخة الأولى.
3. لا نرسل محتوى لمزوّد AI إلا بعد موافقة صريحة لكل تجربة تحليل، مع عرض نطاق البيانات المرسل.
4. كل جواب أو استنتاج يجب أن يميّز بين بيانات المصدر والتحليل الاحتمالي ويُظهر أدلته.
5. لا نستنتج اكتمال أرشيف أو صحة نفسية أو نوايا الآخرين مما لا تثبته الملفات.
6. لا نتجاوز APIs أو صلاحيات منصات ولا نجمع بيانات حسابات أخرى.
7. لا نضيف قياس استخدام يتضمن محتوى خاصًا. أي Telemetry مستقبلية اختيارية وخالية من المحتوى.
8. الاستيراد الآمن، الحذف، والتعامل مع البيانات المؤقتة متطلبات أساسية وليست تحسينات لاحقة.

### خارج نطاق V1

- مزامنة أو تخزين سحابي من طرفنا.
- استيراد تلقائي عبر scraping أو تسجيل دخول إلى منصات التواصل.
- دعم كل المنصات وصيغها دفعة واحدة.
- ادعاء تشخيص نفسي أو تعريف قطعي بهوية المستخدم.
- إرسال أرشيف كامل أو وسائط كاملة إلى نموذج AI.
- العمل بوصفه نسخة احتياطية قابلة لإعادة الاستيراد إلى منصة المصدر.

## 2. قرارات النسخة الأولى

- **الواجهة والمنصة:** Flutter + Dart، Desktop؛ نثبت Windows أول منصة تحقق، ونحافظ على إمكانية macOS وLinux بعد اختبار إضافاتهما.
- **البيانات:** محلية افتراضيًا، في مجلد التطبيق الخاص بالمستخدم.
- **المستورد الأول:** Facebook JSON فقط، بعد الحصول على أمثلة تصدير مشروعة ومنزوعة الهوية للاختبارات. أي نوع ملف غير مدعوم يظهر في تقرير التغطية.
- **قاعدة البيانات:** SQLite عبر Drift، مع migrations؛ واختبار FTS5 على المكتبة المبنية التي ستوزع فعلًا.
- **واجهة الحالة:** Riverpod، مع فصل عناصر الواجهة عن الخدمات.
- **ZIP:** مكتبة `archive` لقراءة المحتوى، مع قيود أمان يفرضها التطبيق. لا نستخدم استخراجًا أعمى إلى مسار المستخدم.
- **اختيار الملفات:** `file_picker`، مع دعم اختيار ZIP أو مجلد حسب المنصة.
- **المفاتيح:** مخزن أسرار نظام التشغيل عند دعم المنصة، لا ملف نصي أو قاعدة البيانات.
- **AI:** واجهة provider عامة قابلة للتبديل؛ BYOK في نسخة لاحقة بعد توثيق شروط كل مزود. لا اختيار مزود قبل مقارنة retention والتكلفة والنماذج.
- **الترخيص:** القرار غير محسوم. Apache-2.0 مناسب للانتشار المرن، AGPL-3.0 قد يناسب اشتراط مشاركة تعديلات النسخة المقدمة كخدمة؛ راجعوا المستشار القانوني قبل نشر LICENSE.
- **Cloud مدفوعة:** لا تُبنى في V1. تُبحث فقط بعد إثبات الحاجة وكتابة نموذج تهديد وبنية حذف واحتفاظ وموافقة.

## 3. المستخدمون والمهام الأساسية

### المستخدم الأساسي

شخص نزّل نسخة بيانات حسابه عبر خيار رسمي ويريد فهم محتواها دون رفع الأرشيف لموقع غير موثوق.

### المهام الأساسية

1. معرفة ما الذي يحتوي عليه الملف قبل استيراده.
2. استيراد البيانات محليًا ومعرفة ما نجح وما تعذر تحليله.
3. البحث عن رسالة أو تعليق/حدث حسب النص والتاريخ والشخص والنوع.
4. استعراض النشاط على خط زمني، وعدم الخلط بين غياب السجل وغياب الحدث.
5. مراجعة إحصاءات قابلة لإعادة الحساب من قاعدة البيانات.
6. طلب تحليل AI اختياري، والاطلاع على مقتطفاته وأدلته قبل الإرسال وبعده.
7. حذف مساحة العمل وبياناتها المحلية.

## 4. وصف الواجهة وتجربة الاستخدام

### إطار التطبيق العام

- تخطيط Desktop ثابت، شريط جانبي للتنقل، منطقة محتوى، وشريط علوي للسياق/البحث.
- حالات واضحة: لم يتم استيراد بيانات، جارٍ الفحص، يحتاج موافقة، جارٍ الاستيراد، اكتمل مع تحذيرات، فشل قابل للتفسير.
- لا نعرض أرقامًا برسوم بلا مصدر أو تعريف. كل بطاقة إحصاء يمكن فتحها لمشاهدة السجلات الداخلة في الحساب.
- دعم لوحة المفاتيح، تكبير النص، قارئ الشاشة، تباين مناسب، واتجاه RTL كامل للعربية مع دعم LTR للمحتوى الإنجليزي.
- كل النصوص المعروضة للمستخدم قابلة للترجمة، ولا تُضمّن نصوصًا أصلية من ملفات المستخدم داخل تقارير الأعطال.

### الشاشات

#### أ. البداية والخصوصية

- وصف موجز: “بياناتك تبقى على جهازك، وAI الخارجي اختياري”.
- شرح منفصل للتخزين المحلي ولإرسال مقتطفات إلى API إن فُعّل.
- أزرار: استيراد أرشيف، قراءة سياسة الخصوصية، فتح مشروع سابق.
- لا تطلب إنشاء حساب.

#### ب. اختيار البيانات وفحص الأرشيف

- زر اختيار ZIP أو مجلد.
- عرض اسم الملف وحجمه والمساحة المقدرة بعد القراءة.
- فحص أسماء الملفات والأنواع والبنية، دون تنفيذ أي محتوى.
- شاشة مراجعة قبل الاستيراد تبين أنواع البيانات المكتشفة وغير المدعومة وحدود الحجم.
- لا يتم فك الملفات إلى موقع عام أو إنشاء روابط رمزية.

#### ج. تقرير الاستيراد

- تقدم العملية وعدد الملفات المقروءة.
- ملخص: سجلات رسائل/تعليقات/تفاعلات/وسائط إن أمكن التحقق منها من المصدر.
- قائمة أخطاء لكل ملف مع مسار نسبي، ورمز خطأ غير حساس، وإجراء مقترح.
- توضيح أن الملف لا يضمن اكتمال كل تاريخ الحساب.
- إلغاء العملية يحذف نواتجها المؤقتة ويترك قاعدة البيانات في حالة سليمة.

#### د. نظرة عامة

- فترة النشاط المتاحة ومصدرها.
- نشاط شهري/يومي، وتوزيع لأنواع الأحداث الموجودة فعلًا.
- أكثر المحادثات/الأشخاص ظهورًا حسب عداد محدد، بلا ادعاء قرب أو جودة علاقة.
- كل رقم يفتح السجلات المصدرية.

#### هـ. البحث المتقدم

- حقل بحث نصي، تاريخ بداية/نهاية، منصة، نوع حدث، مشارك، ومرشحات إضافية متاحة حسب المستورد.
- ترتيب بالتاريخ أو صلة FTS.
- نتيجة تحتوي اقتباسًا محدودًا، اسم مصدر، تاريخًا، وفتح التفاصيل.
- ترميز إدخال بحث FTS بأمان؛ إدخال المستخدم لا يتحول إلى SQL.
- حالة صفر نتائج تشرح المرشحات النشطة.

#### و. Timeline

- تجميع بحسب يوم/شهر مع اختيار مستوى العرض.
- المرشحات نفسها الموجودة بالبحث.
- الأحداث ترتب وفق وقت المصدر مع عرض المنطقة الزمنية/غيابها.
- عدم عرض حدث مجهول التاريخ كما لو كان دقيقًا.

#### ز. العلاقات

- رسم/قائمة قابلة للوصول بلوحة المفاتيح.
- وزن العقدة يعرف بوضوح (عدد الرسائل مثلًا)، مع مرشحات زمنية.
- لا استنتاج مشاعر أو نوايا الطرف الآخر دون دليل، ولا وصف بياني مضلل.
- عند غياب هوية ثابتة، تُعرض الأسماء كما وردت دون دمج تخميني.

#### ح. Agent Chat

- اختيار مساحة البيانات والفترة وأنواع المحتوى التي يسمح بتحليلها.
- قبل أول طلب خارجي: اسم المزوّد، البيانات التي ستخرج، وسياسة احتفاظ مختصرة ورابطها، وتكلفة تقديرية إن توفرت.
- خطوة مراجعة/موافقة قبل كل إرسال أو حسب إذن دائم واضح قابل للإلغاء.
- الرد يحتوي مصادر قابلة للنقر، ويصرح عند قصور البيانات.
- لا يصدر استعلام SQL من النموذج مباشرة؛ ينفذ النظام أدوات داخلية محددة فقط.

#### ط. “Tell me exactly who I am”

- العنوان التسويقي لا يغير حقيقة أن التقرير استنتاج محدود من أرشيف ناقص.
- أقسام: أنماط الموضوعات، النشاط عبر الزمن، أشخاص يظهرون كثيرًا، ملاحظات قد تفاجئك، وما لا يمكن استنتاجه.
- كل بطاقة: النتيجة، أمثلة مصادر، الفترة المشمولة، عدد العينات، درجة/وصف ثقة مفهوم، تفسير بديل، وزر تصحيح/إخفاء.
- يمنع تشخيص اضطراب، تقرير صفات سريرية، أو تقرير حقيقة ثابتة عن شخصية المستخدم.

#### ي. الإعدادات والخصوصية

- مساحة البيانات الحالية وموقع التخزين.
- إعداد AI منفصل لكل مزود، واختبار اتصال لا يرسل محتوى الأرشيف.
- سجل موافقات الإرسال ونطاقها دون حفظ محتوى حساس زائد.
- حذف مساحة العمل ومرفقاتها، وتأكيد واضح قبل التنفيذ.
- توضيح أن إزالة ملف من قاعدة بيانات لا تضمن overwrite آمنًا على أقراص SSD أو النسخ الاحتياطية الخارجية.

## 5. العمارة البرمجية

```text
Flutter Widgets
  └── Riverpod providers/controllers
      └── Application use-cases
          ├── ImportCoordinator
          │   ├── ArchiveInspector (untrusted ZIP; quotas; no unsafe extract)
          │   ├── FacebookJsonImporter
          │   ├── Unified event mapping
          │   └── Transactional repository writes
          ├── SearchRepository (SQLite FTS5 + structured filters)
          ├── Timeline/Analytics services (deterministic SQL)
          ├── Retrieval service (bounded, cited evidence)
          └── AI provider interface (optional, consent gated)
              └── provider implementation(s), added only after review
      └── Drift database + local media store + OS secret store
```

### قواعد الحدود

- Widgets لا تقرأ ملفات ZIP ولا تشغل SQL.
- Importer لا يرسل شبكة.
- مخزن الأحداث هو المصدر الأساسي؛ الملخصات ونتائج AI مشتقة ويمكن حذفها/إعادة بنائها.
- واجهة مزود AI تأخذ حزمة أدلة محدودة بعد موافقة، لا مسار الأرشيف أو قاعدة البيانات.
- تكون migrations مرتبة وقابلة للاختبار، وكل import مرتبط بـImport ID.
- كل الأخطاء للمستخدم آمنة ولا تضع نص الرسائل في السجلات.

### تنظيم المجلدات المستهدف

```text
lib/src/
  app/                 إعداد التطبيق والتنقل والثيم
  core/                أخطاء، logging منقح، أدوات أمان
  domain/models/       نماذج مستقلة عن قاعدة البيانات
  domain/repositories/ واجهات المستودعات
  data/database/       Drift، الجداول، migrations، DAOs
  data/importers/      مستورد مستقل لكل منصة وصيغة
  data/media/          روابط وعمليات وسائط محلية
  features/import/     سير الاستيراد والشاشات
  features/search/     البحث والنتائج
  features/timeline/   خط الزمن
  features/overview/   لوحة النظرة العامة
  features/agent/      المحادثة والموافقة والمصادر
  features/identity/   تقرير الأنماط
  services/analytics/  مؤشرات حتمية
  services/retrieval/  اختيار الأدلة
  services/ai/         واجهة ومزوّدات AI اختيارية
```

## 6. مخطط البيانات الأولي

- `imports`: id، platform، format، source fingerprint، started/completed، importer version، status.
- `source_files`: id، import_id، relative_path، media_type، hash، parse_status، safe error code.
- `people`: id، platform، platform-scoped id nullable، display name as exported؛ لا دمج بالاسم وحده.
- `conversations`: id، import_id، source id nullable، title nullable.
- `events`: id، import_id، source_file_id، source_locator، platform، event_type، timestamp raw، timestamp normalized nullable، timezone status، actor id nullable، conversation id nullable، text nullable، metadata JSON allowlist.
- `attachments`: id، event_id nullable، source_file_id، relative path nullable، media type، length/hash.
- `event_search`: FTS5 virtual table مرتبط بالنصوص المطلوبة فقط، مع حذف/إعادة بناء متزامنين مع السجلات.
- `derived_insights`: id، created_at، scope، method/version، evidence event IDs، confidence label، content؛ يمكن حذفها وإعادة بنائها.
- `ai_consents`: سجل قرار وإصدار سياسة ونطاق، لا يحتفظ بالمقتطفات نفسها.

لا نخزّن تعليقات/حقول اعتباطية كاملة في JSON بلا حد؛ نحدد allowlist ونضع حدًا لطول النصوص والبيانات.

## 7. الاستيراد الآمن

- تحديد حد موثق لحجم ZIP، وعدد entries، والحجم الكلي بعد فك الضغط، وحد لكل entry، وحد للوقت/الذاكرة، مع إعدادات معقولة قابلة للتعديل مستقبلًا.
- رفض المسارات المطلقة، `..`، محارف NUL، وأسماء الملفات المكررة/المربكة؛ رفض symlinks/hardlinks ما لم نثبت الحاجة.
- لا نفك الأرشيف كله إلى مسار يختاره المستخدم. نقرأ entries أو ننسخ allowlist إلى staging خاص، خارج مسارات الويب/المزامنة العامة.
- التحقق من الحجم الفعلي أثناء القراءة؛ لا الاعتماد على metadata المصرح بها داخل الأرشيف.
- إلغاء العملية يوقف القراءة ويحذف staging. كل عمليات الكتابة في transaction أو staging ثم commit.
- تحليل JSON بحدود للعمق والحجم، قبول المفاتيح المتوقعة، وإظهار الملفات غير المعروفة دون تخمين.
- عينات الاختبار لا تتضمن بيانات فعلية شخصية؛ كل عينة مرخصة ومنزوعة الهوية.

## 8. AI وخصوصية البيانات

- Provider-agnostic interface وBYOK؛ لا مفتاح مضمّن في المصدر أو الإعدادات العادية.
- الميزة الأساسية تعمل بلا شبكة.
- لا رفع ملفات للـprovider في V1؛ فقط مقتطفات نصية محددة بعد موافقة ومراجعة للمستخدم.
- retrieval محلي؛ اختيار أدلة مرتبط بالسؤال، مع حد أعلى للطول والعدد.
- إزالة/تقليل بيانات حساسة حسب خيار المستخدم، مع عدم وعد إزالة كل معلومة تعرفية ممكنة.
- تصفية حقن التعليمات: محتوى المستخدم المستورد يُعرض كنص غير موثوق؛ لا يمكنه تغيير أدوات النظام أو سياسة المساعد.
- response parsing مضبوط، وعدم تنفيذ كود أو URL أو SQL صادر من النموذج.
- قياس التكلفة قبل الإرسال إن أمكن، ورفض/تحذير إذا لا يمكن تقديرها.
- تسجيل مزود ونموذج وتاريخ ونطاق موافقة، لا نص الأرشيف/مفتاح/API response الخام.
- قبل اختيار مزود: تدقيق شروط الاستخدام، التدريب، retention، abuse monitoring، الملفات، residency، حذف البيانات، والسعر؛ إظهار الرابط والتاريخ للمستخدم.
- عبارات المنتج القانونية لا تُكتب كضمانات مطلقة، وتراجع قانونيًا.

## 9. مكتبات ومشاريع مفتوحة المصدر المرشحة

الاعتماد النهائي يتطلب تدقيق الإصدار والرخصة وبناء التطبيق على OS الهدف؛ الأسماء هنا ترشيحات، لا ضمان توافق لكل إصدار.

| المشروع | الاستخدام | طريقة الدمج | ملاحظات |
|---|---|---|---|
| Flutter | UI وتطبيقات Desktop | SDK رسمي + build لكل target | تحقق من دعم الإضافات لكل نظام. |
| Riverpod / flutter_riverpod | فصل الحالة والاعتمادات | Controllers/Providers فوق services | لا يوضع parsing أو SQL في widgets. |
| Drift | SQLite وmigrations وqueries | DAOs و`.drift` SQL عند FTS | اختبر extension على build الموزع. |
| sqlite3 | محرك SQLite الأصلي | backend لـDrift على Desktop | تحديثات وبناء native لها تبعات توزيع. |
| archive | قراءة ZIP | inspect entries، قيود حجم، parse بلا extraction أعمى | لا يغني عن دفاعات Zip Slip/zip bombs. |
| file_picker | Native file picker | اختيار ZIP أو مجلد ثم تمرير المسار لخدمة الاستيراد | API يتغير بين الإصدارات الكبرى؛ اختبر target OS. |
| path_provider | مسار بيانات التطبيق | DB/media داخل Application Support | لا تستخدم Desktop Documents العامة افتراضيًا. |
| flutter_secure_storage | أسرار النظام | حفظ مفتاح DB أو API إن توفر الدعم | يحتاج keyring/configuration واختبار packaging. |
| flutter_test / integration_test | unit/widget/platform tests | fixtures صناعية منزوعة الهوية | اختبر التوافق الحقيقي والتوزيع، لا mocks وحدها. |

### تشفير قاعدة البيانات

Drift/SQLite لا يعني تلقائيًا تشفيرًا على القرص. قبل تفعيل خاصية “قاعدة مشفرة” اختر cipher/build بقرار موثق، اختبر FTS5 وmigration وإعادة الفتح والمفاتيح الخاطئة على كل منصة، واعرض رخصة كل binary ومكوناته. `flutter_secure_storage` يخزن سرًا ولا يشفر قاعدة البيانات بذاته. أما الوسائط والملفات المؤقتة فلها مسار حماية مستقل. لا ندّعي تشفيرًا حتى تثبت اختبارات النسخة الموزعة ذلك.

## 10. الاختبار والجودة

### وحدات

- parser لكل JSON shape مدعوم، مع الحقول المفقودة والاختلافات.
- timezones والتواريخ غير الصالحة.
- deduplication وsource locators.
- قواعد quota والمسارات وsymlinks وZIP malformed/oversized.
- البحث FTS5 بالعربية والإنجليزية وعلامات الترقيم وoperators.
- analytics تعيد نفس النتيجة لمجموعة بيانات ثابتة.
- منع الشبكة داخل Importer.

### تكامل وقاعدة بيانات

- migrations من كل إصدار مدعوم.
- transaction/rollback عند فشل منتصف import.
- تنظيف ملفات staging بعد النجاح والفشل والإلغاء.
- indexing/backfill/hide/delete في FTS.
- فحص FTS5 وتشفير DB على binary الموزع إذا اعتمد.

### واجهة وتوزيع

- حالة أول تشغيل، import progress/error/cancel، empty search، RTL، keyboard navigation.
- file-picker وsecure-store لكل OS مدعوم.
- اختبار build نظيف على أجهزة/CI لكل نظام تشغيل معلن.
- فحص dependency licenses وSBOM/الإصدارات عند التحضير للإصدار.

## 11. خطة المراحل ومعايير القبول

### المرحلة 0 — تأسيس المستودع

README عربي/إنجليزي مختصر، قرار الترخيص، تنظيم الملفات، Flutter project، CI للفحص والاختبار. **قبول:** مشروع نظيف يبني على الهدف الأول، ولا توجد مفاتيح أو بيانات شخصية.

### المرحلة 1 — نماذج قاعدة البيانات

Imports/events/source_files، migrations، FTS5 probe. **قبول:** اختبار DB يعيد إنشاء الجداول والفهرس على native target.

### المرحلة 2 — استيراد Facebook JSON تجريبي

Inspector آمن، تقرير تغطية، importer لنوع بيانات واحد مثبت بعينة فعلية مرخصة. **قبول:** لا extraction خارج staging؛ malformed/oversized archive تفشل برسالة مفهومة.

### المرحلة 3 — توسيع المستورد

رسائل/تعليقات/تفاعلات بالتتابع حسب ملفات المصدر الحقيقية. **قبول:** كل فئة مدعومة لها اختبار fixture ومصدر محفوظ.

### المرحلة 4 — البحث والتصفح

بحث فوري، مرشحات، صفحة تفاصيل، pagination. **قبول:** كل نتيجة تشير لمصدرها وتُحذف من FTS عند حذف الأصل.

### المرحلة 5 — Timeline والتحليلات المحلية

تجميع وقتي وإحصاءات موثقة. **قبول:** النتائج حتمية ومقارنة مع استعلامات مرجعية.

### المرحلة 6 — Agent مع BYOK

واجهة provider، تخزين سر آمن، retrieval ومراجعة قبل الإرسال. **قبول:** الاختبارات تثبت أن لا طلب شبكة قبل الموافقة وأن السياق محدود ومُستشهد به.

### المرحلة 7 — تقرير الهوية والواجهات المتقدمة

تحليلات متدرجة، أدلة/قيود، شبكة علاقات. **قبول:** كل استنتاج له evidence IDs، ولا توجد صياغة تشخيصية.

### المرحلة 8 — توسيع الصيغ والنشر

مستورد جديد واحد كل مرة، اختبارات عينات ورخصة وقيود. Cloud ليست ضمن هذه المرحلة تلقائيًا.

## 12. تنظيم العمل مع نموذج برمجة

1. اطلب منه تنفيذ **مرحلة واحدة فقط** من هذه الخطة في كل دفعة.
2. اطلب منه قراءة الملفات الحالية والـREADME قبل التعديل.
3. اطلب tests مع كل importer أو service، وشغّل fmt/analyze/test قبل الانتقال.
4. لا تسمح له باختراع مفاتيح أو نماذج تصدير غير موثقة؛ يطلب عينة منزوعة الهوية عند الحاجة.
5. راجع `git diff` بعد كل دفعة، ولا تدمج بيانات حقيقية أو مفاتيح أو ملفات التصدير بالمستودع.
6. لا تطلب commit/push/deploy تلقائيًا؛ هذا يحتاج تفويضًا منفصلًا.

## 13. سجل القرارات المفتوحة

- اسم المنتج وهوية بصرية.
- Windows فقط أولًا أم دعم Windows/macOS/Linux من أول إصدار.
- ترخيص المشروع بعد مراجعة قانونية.
- مصدر/ترخيص عينات Facebook المنزوعة الهوية.
- أي أجزاء فعلية من Facebook JSON تدعم أولًا؛ يتحدد بعد فحص عينة حقيقية.
- cipher/database encryption ومسؤولية التوزيع والنسخ الاحتياطي.
- أول مزود AI وشروط retention والتكلفة.
- هل توجد حاجة لاحقة لـCloud، وما بياناتها التي ستخزن ومدة الاحتفاظ.
